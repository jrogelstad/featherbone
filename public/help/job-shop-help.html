Workbooks

Click on a menu item on the list to open the respective workbook.

Clicking on the arrow on the top of the menu will collapse it, as shown below, to enable more space for worksheets on the screen. Click on the arrow again to expand the menu. Hover over a menu item to show the descriptive title of the workbook.

Workbook menu collapsed

Note that the web address at the top of the workbook can be copied and sent to other people in your organization to take them directly to the same page if they have access to the workbook.

User account menu

The user account menu is the third button from the right at the top of every page. From this menu, you have three menu items that work as follows:

Info

This item lets you view and change contact information linked to your account.

Dialog to change user account contact information

Dialog to change your password

Managing workbooks#

Adding a workbook

Adding a workbook is a global function that requires administrator privileges. To learn how to do this, please go to managing workbook templates.

Editing a workbook

You can navigate to workbook settings on the second button from the right where you will be presented with the workbook settings dialog which has two tabs.

Edit workbook action in workbook manager menu

Definition

Edit workbook dialog – definition tab

Here you can change the description, override the label that appears on the menu button, the icon that is used and the sequence it appears in the list. Also note if you have administrator privileges you can entirely delete the workbook here.

Authorizations

Edit workbook dialog – Authorizations tab

The authorizations tab controls who can see and alter the workbook. From here you can assign standard Job Shop business roles or individual user accounts. Job Shop comes pre configured with appropriate roles assigned to workbooks, but users with roles that have update access to the workbook are allowed to edit the list.

Roles that have read access are allowed to see the workbook, along with all pages within it. Read only roles are allowed to rearrange column headers, change filters, sorting and subtotals, however the workbook will reset to its original state when the page is refreshed. In addition, read only users are not allowed to open the workbook or worksheet settings dialogs to make changes.

When a user has a role with update access to a workbook, Featherbone will remember any local changes they have made to column headers, filters, sorting and subtotals with their user account. These settings will stick when the page is refreshed or when they log into another machine. Furthermore, users with update privileges are allowed to edit both workbook and worksheet settings and share their changes with others. See sharing changes for more information.

Note: If a user has a role to read or update a workbook but does not have a role necessary to read the content of one or more of the worksheet pages, they will not see any data listed. To see data the user must be granted a role allowed to read it. See role authorization for more information.

Sharing changes#

If you have update privileges for a workbook and you make changes to one or more worksheets including adding new pages, changed columns, filters etc., you can share your changes with the rest of the organization by selecting Share on the workbook management menu.

Share action in workbook configuration menu

When sharing you are prompted to select one of four options:

Share dialog prompt

Default for this workbook

This option will make your workbook configuration the default for all users. For read only users, or users with update privileges who have made no changes to their workbook, they will see your configuration on the next page refresh. For users with update privileges who have made any changes, they will only see the default if they revert their existing workbook.

Copy to a new workbook

Select this option to make a new workbook that is identical to the current one. This is a good option if you want to make a version of the workbook that you have modified for a particular user group, but don’t want to have to start from scratch to build it. When choosing this option, you will be prompted to give the new copy a name.

Share workbook with copy option selected

After giving it a name and clicking “Ok” the copy will immediately appear.

New workbook template

This option will make an internal workbook template that can be used to generate new similar workbooks. This is a good option if, for example, you intend to make a series of workbooks for the shop floor that are pre-filtered to work center specific criteria. Like copying a workbook, you must give the template a name.

You must have the administrator role to create new workbooks using templates. To learn how to do this, please go to managing workbook templates.

Update to a template

Choose this option to update an existing template to reflect the current workbook configuration.

Note: this option only updates the template, not workbooks that were previously created with the template.

Reverting changes

Users who have update privileges to a workbook can choose this action to revert their workbook personalization back to the default configuration.

Worksheets have a mode control in the upper left corner that is disabled by default for most pages.

How to use search

The search bar at the top of every list does a case-insensitive match on the text of every visible column within that page. In the example below results are returned where “wire” is found within the number and description columns.

Because search is a matching function, it supports regular expressions which can get quite sophisticated. We will only show a few examples of some of the more commonly used techniques:

Use the | symbol between two texts to do a search between one text OR another.

Use the ^ symbol in front of a word to search for text that starts with it.

Use the $ symbol after a word to search for text ending with that word.

Regular expressions are a standardized concept in computer science and are not unique to Featherbone. An internet search on “regular expression tutorial” will return many results that further explain the powerful, and potentially complex, capability of this matching logic you can use.

Showing deleted records

There is also an option when filtering to show deleted records. When records are deleted in Featherbone, in most cases it does a soft delete, which means the records are flagged as deleted internally but are still present and just not shown in lists and searches except when specifically called for. Being able to show deleted records is useful for auditing purposes.

Note many records such as products, sales orders and shipments cannot even be soft deleted once a transaction has been performed against them.

To show deleted records, just check the box at the bottom of the filter list.

Lazy loading

It’s worth mentioning that Featherbone uses a technique called “lazy loading” to improve usability. This means that it initially only loads a few more records than can be made visible on your screen. As you scroll down the list, it will continue to load more records as you scroll until all of them are loaded. This prevents you from having to wait a long time to load lists that may be thousands or tens of thousand of records. Typically, it’s expected if there are that many records in the system, you will search or filter until you narrow to a short list.

Adding and removing worksheets#

Adding a worksheet

Users with update privileges on a workbook can add a new worksheet by clicking the right most “+” tab and will be presented with the dialog below.

Adding a new worksheet

By default, the feather will be the same as the active worksheet from where the add button was clicked. From here the worksheet should be renamed something meaningful. Columns will also be copied from the active worksheet. However, if a different feather is chosen only columns common to both the original workbook and the new feather will be preserved. Once you click “Ok” the new worksheet becomes part of the workbook. Any filters, sorting or subtotals need to be applied to make it useful for its intended context.

For other users to see and use this new worksheet, the revised workbook needs to be shared as the new default. Other users with update privileges may need to revert to the new default to see it if they have also already made changes that have effectively customized their view of the workbook. Otherwise, users with read only privileges will automatically see the changes since they always see the current default after a page refresh.

Export

You may export all the data in the list to a file in popular formats including Excel, Open Document Spreadsheet and JavaScript Object Notation (JSON).

Export dialog

This can be useful to create highly tailored reports, but also if you intend to do some kind of mass editing that would otherwise be too tedious to do record by record in Featherbone, even using inline editing. Exported records can be imported from the same menu to apply mass changes to your records. Note, however, if the purpose is to mass update, it is a good idea to uncheck “Only visible columns” so that all data is exported rather than only the data you can see in the worksheet.

Import

Use import to mass load new records or mass update existing records. The format of import files is very particular, we recommend you export all columns of a worksheet first to establish the format, then add or edit records in the exported file following the format provided.

Export file with call outs

The above image of an Excel export with callouts displays a few things worth noting about the file format.

Unique identifier

All records have a globally unique identifier. These are generated automatically if created in Featherbone. If you create new external records yourself this value can be anything, just be sure it is globally unique. In other words, no other records can share this value.

Natural key

Most document records also have a key that is unique to the feather, which is meaningful to, and therefore more readable, for humans. Typically, this column is “code”, “number” or “name.” Since it is only unique to the feather, other feathers may have a natural key with the same value. For instance, there may be both a product “category” and “group” with a code “Finished Goods.”

Note, however, not all records have a natural key. For example, the feathers “Address” and “Contact” do not have this.

Relation natural keys

To make reading and managing exports and imports easier, relations use the natural keys as a reference in spreadsheet files. Note that the record with the natural key referenced must pre-exist for the import to succeed. For example, to import products with category of “Finished Goods,” that category must be created or imported in Featherbone first.

If a relation (such as address or contact) does not have a natural key, the Id is used as the reference.

Child records

When feathers have child records, these are represented as additional tabs on spreadsheets, which makes it possible to import complete document objects. Child records must reference the Id of the parent.

Concepts

What is Featherbone?#

In this guide you will see references to both “Featherbone” and “Job Shop,” which may be a bit confusing at first. How is Featherbone different from Job Shop? Featherbone is the framework that provides the structure and navigational elements to build a database application, like the way you use your favorite spreadsheet program to build a series of tables and data. Job Shop is a specific application built on Featherbone to help manufacturers run their business. When we talk about Featherbone, we’re talking about general principles that apply throughout the system. When we talk about Job Shop, we’re talking about a specific feature built in the Job Shop application to support the manufacturing cycle.

Editions

Job Shop itself has three editions: Standard, Professional and Enterprise where Standard provides functionality needed for material control, Professional adds tools for operations management, and Enterprise adds capabilities for more mature companies such as physical inventory count. This document will call out when certain features are only available in certain editions.

The order to cash life cycle#

Job Shop helps small to medium-size businesses monetize their business by helping to coordinate documents, materials and activities involved in making specialized products. This article will explain how Job Shop supports sales, purchasing, manufacturing and billing activities for a variety of business models.

Make to Order

The diagram below shows an example of a typical make-to-order workflow in a job shop environment, which in this case assumes all products involved need to be acquired and assembled to ship and complete a sale. The bold word (for example, “Design”) is the workbook where the document type is found, while the word underneath (for example, “Products”) is a particular document type, also known as a feather, within the workbook.

Example of a typical Job Shop workflow

Design Products

Here you define the products you buy and sell. It includes the bill of material needed to make them, or suppliers for purchased products, and the costs. In the flow chart above, the product being sold is defined before a sales order is created, but it is not unusual in job shops to get an order for the item first, and only then define how to buy or make the parts needed to ship the order.

Sell Sales Order

The sales order is where you list one or more parts you are selling to a customer, including the quantities, prices, taxes, shipment addresses, billing parties and so forth. Sales order lines are a type of demand signal that products are needed to execute business. Products can also be kits, which signal demand for a collection of parts that ship together. Job Shop supports the ability to automatically create work orders to build any necessary products that need to be shipped.

If you require a deposit to start work, or use any form of milestone billing, you can optionally create a prepaid invoice to send to the customer for collecting payment before products ship.

You can also optionally print or send an order confirmation document to customers so they know when they can expect you to ship the order

Buy Purchase Order

In the flow diagram above, a demand signal was created to buy parts for manufactured products being sold. In this case, we create a purchase order in response to fulfill that demand. A purchase order defines who we are buying from, what we are buying, how many, the price of the parts, and expected receipt date so we can keep track of what products are coming and when.

Job Shop enables you to print and send purchase order documents to suppliers.

Buy Purchase Order Receipt

When the purchased products arrive, we record a purchase order receipt, which automatically increases the on-hand inventory quantity for the products received and reduces the outstanding purchase order quantity. When all quantities are received, the purchase order closes automatically.

Make Work Order

A work order describes how and when you want to make products. Work orders may be automatically created when a particular sales order is ready to start. However, they can also be made manually at any time to produce products for inventory.

Work orders copy the bill of materials from the product being made to the work order materials list to signal what products are needed to complete the job. If the materials are not already on hand, you may get a signal to purchase them, or even child work orders automatically created to build parts needed to make the final product. In supply chain jargon these work order materials are known as dependent demands because the product being sold depends on other parts being acquired to make and ship the final product.

You can optionally print a work order traveler document that includes the order number and describes how to do the work.

Make Work Order Receipt

Once work order products have been manufactured, we need to record their completion. This increases inventory for the products received, decreases inventory of all the materials needed to make it, and reduces the quantity due on the work order. The work order closes automatically when all quantities have been received.

Ship Sales Order Shipment

When any or all items on a sales order are ready to ship, you can optionally print a pick list that tells your shipping team what products to gather for shipping. Once this is done, you create a shipment record specifying what parts are shipping (as it is possible and even normal to only ship part of an order). Once this information is complete, you ship (meaning complete) the shipment which then subtracts the parts from inventory, reduces the sales order demand, and even closes the sales order if all quantities have been shipped.

You can optionally print a pack slip to include with the shipment that shows the order number, which parts were shipped and how many. If you have set up Ship Engine integration, you can also print shipping labels to attach to the shipping containers which transport companies can use to scan and track your packages.

Bill Shipment Invoice

From the shipment record you can create an invoice for the parts that are shipped including any additional shipping charges and taxes. If any prepaid invoices were created for the order, they will be applied to and deducted from the shipment invoice. Once created, you can print and send the invoice document to your customer.

Bill Apply payment

Once payment is received you apply it to the applicable invoice which reduces the amount due on the invoice or closes it if it is paid in full.

  • Number — A unique identifier for the product. You can change the number until the time it is shipped, at which point it becomes read only.

Likewise, expense products listed as materials on a work order only update on the work order level. Product bill of materials#

The bill of material (BOM) defines a collection of parts that go into manufacturing a product, or that constitute a kit. Note that all the parts on a bill of material must also have inventory set up for the site where you make, buy or sell the parent product, otherwise Job Shop will throw an error. The common BOM attributes included on the table view in the products form are:

  • Sequence — Automatic number assigned to the bill of material row, starting from 1. Moving parts up or down in the list will automatically reassign the sequence numbers in order.
  • Product — A product used to manufacture the parent, or within the kit.
  • Quantity Per — The number of parts needed for each parent part manufactured, or kit sold or purchased.

Example 1: A part “Bicycle” requires a quantity of 2 tires per cycle. The tires are Inventory parts.

  • If the bicycle is an Inventory item, and a work order for 100 bicycles is launched, 200 tires will be required to satisfy making the bicycles. The tires will be deducted from inventory when an operation linked to them is posted, or otherwise when a work order receipt is posted.
  • If the bicycle is a Kit product and a sales order is created that calls for 100 bicycles, when the bicycles are shipped, 200 tires will be deducted from inventory.
  • If the bicycle is a Kit part and a purchase order is created that calls for 10 bicycles, when the bicycles are received, 20 tires will be added to inventory
  • Fixed Quantity — A quantity of the part that needed for the parent part regardless of how many parent parts are manufactured, purchased, or shipped. The logic of fixed quantity is the same for manufactured or kit parent parts.

Example 2: A part “Bicycle” requires a quantity of 6 fluid ounces of paint per cycle. However, in the process of painting bicycles, there is always 20 ounces of paint used during startup doing flush and test sprays. The paint is an Inventory part tracked in gallons. There are 128 fluid ounces per gallon.

  • If the bicycle is an Inventory item, and a work order for 100 bicycles is launched, 4.84 gallons of paint will be required to satisfy making the bicycles:
  • (100 gallons * 6 fl. oz. per cycle + 20 fl. oz. fixed quantity) / 128 fl. oz. per gal. = 4.84 gal.
  • The fixed paint quantity will be deducted from inventory when any quantity of operation linked to painting (if it exists) is completed, or otherwise when any work order receipt is recorded.

Example 3: A kit part “Bicycle” requires a fixed quantity of 1 and 0 quantity per assembly instruction booklets.

  • If a sales order is created for 100 bicycle kits, one assembly instruction booklet will be deducted from inventory when the bicycles are shipped.
  • Operation number (Op#)* — This links the material you consume to a specific operation sequence number listed in the operations tab.

How the item life cycle works#

Overview

Products define a type of physical item that you can buy, make, sell, and optionally carry in inventory. Specifically, products include bill of material and router* definition support that describe how a product is made, or in the case of a kit, what materials make up the kit when it is bought or sold.

Services define a type of work an outside processor can perform on a work order in lieu of your shop doing the work itself. These services are set on operations, when applicable, and copy down to work orders when they are created. It is up to you whether to track the progress of services in detail, but if you do decide to track them this is done by creating a purchase order tied to the work order service requirement and recording shipment and receipt of goods processed by the supplier. It’s notable that services cannot be held in inventory, and must be processed on a purchase-to-order basis.

What are “items”?

Both products and services are a type of item and any purchase in Job Shop is likewise for an item. Job Shop organizes data this way so that a line on a purchase order can be either for a product or service but is handled the same way. Therefore, whenever you see a reference to an “item” in Job Shop, this is for a record that could be either a product or a service.

The item life cycle

Product statuses

As shown above, an item can be set to have one of three statuses that work as follows:

  • Pending — This is the default status for new items. You should use pending when you are still designing your item and is not ready to be bought, made, or sold. You can roll up costs on pending items that are products, and products that contain pending products in their bill of material, but you may not use pending products in inventory, purchase orders, work orders or sales orders.
  • Active — Items in this state can be used throughout the system for inventory, orders, planning and transactions. Once a product has transaction history or open or orders, it can no longer be deleted. Also, if a product has active inventory or orders, it cannot be changed to pending or inactive until the inventory is zero and all related orders are closed or deleted.
  • Inactive — Items should be changed to this state when they are obsolete, and you no longer want to allow them to be used in your business. Inactive items have the same restrictions as pending ones, except that they cannot be used in cost roll-ups. The system will throw an error if you attempt to roll up costs on a product that contains an inactive product in its bill of materials.

Global conversions#

The Conversions tab within the Design workbook lists all global unit of measure conversions from one item unit to another. These are used to calculate impact on the stock unit of measure for a product when a different unit is called for than the stocking unit. For example the stock unit for paint may be gallons, but a bill of material might call for a certain number of fluid ounces to paint a product. These conversions allow the calculation of how many gallons will be needed to make a particular product automatically. Global conversions must be between two item units of the same dimension, such as length, area or volume. So, for example, you can convert centimeters to meters because these are both lengths, but you cannot convert centimeters to liters where the first is a length and the second is volume.

Planning concepts overview#

Job Shop has a heavy emphasis on material planning because having materials on hand to work with is both physically necessary and is often one of the most difficult things to manage when a shop starts to get busy and complicated. Pro and Enterprise editions also support operational planning to help work out lead times and task lists using lead time buffers to manage the ebb and flow of capacity availability.

Three ways to handle material planning

There are effectively three ways to manage planning in Job Shop. We’ll list them here from the least to most sophisticated.

Offline planning

Sometimes it is useful to call out a product on a bill of materials that is helpful for costing and shop floor information on a traveller, but it is not worth keeping track of stock levels in detail. Examples of these kinds of products are adhesives, tapes, paper, spacers, labels and other consumable materials. In this case you should set the product type as expense so that it can be referenced on bills of materials, purchased or even sold, without involving the overhead of tracking quantities in inventory. Actual replenishment of these products will need to be done offline using kanban, paper reorder forms or some other physical system.

Reorder point

Products with the type set to inventory and planning policy set to reorder point appear on shortage and reorder worksheets when stock quantities are currently or projected to fall below the reorder point quantity set on the product site inventory settings. The chart below shows how reorder point managed inventory fluctuates over time. As stock draws down and hits the reorder point, planners are triggered to launch a new supply order which could be either a purchase order or a work order. Typically new supply has a lead time of days, weeks or even months to process before it is received in inventory. Therefore the reorder point quantity should allow enough time for a supply order to be delivered, based on historic usage rates and lead times, before it falls below its safety stock.

Reorder point usage over time

Stock managed by reorder point is tracked anonymously within inventory. In other words Job Shop does not keep track of whether any particular inventory supply “belongs” to a demand that needs it. Typical candidates for reorder point management are products that have significant lead time, predictable usage and modest value. Examples of products that might be good candidates include common lumber and sheet metal, paint, fasteners, hardware and wire.

Allocated supply

When the planning policy for inventory products is set to plan-to-order or make-to-order then demands for these products are allocated to specific supplies. For example, in the screenshot below we have a sales order supply timeline where there are allocations between four work orders that visually help us understand their relationships to one another. The assemblies on work orders W-00027-2, W-00027-3 and W-00027-4 are all allocated to the material requirements for the finished assembly on W-00027-1 which in turn is allocated to satisfy sales order S-00009\1 demand itself.

Allocation based planning is best for infrequently used or expensive inventory products where you prefer to make or buy only what is necessary to satisfy active demands. Examples include low volume sub assemblies, specialty wood or metals, electronics, servo motors, and exotic valves.

Automatic planning

Product sites set for plan-to-order and make-to-order are automatically planned when demand is in a ready state. For sales orders this is when status moves from incomplete to pending or released. For work orders this happens when they are exploded which occurs automatically on the initial save. Automatic planning means the demands are planned as follows:

  1. If inventory is available it is allocated to the demand.
  2. If there are any active supply orders with unallocated quantity they are allocated to the demand until all supply quantity is allocated or the demand is satisfied.
  3. If there is any remaining unfulfilled demand, new supply is created according to the demand product site’s planning policy as follows: - Plan-to-order: One or more planned orders are created for the balance according to order increment and min/max rules. - Make-to-order: A work order is created which is automatically planned recursively following this same process for each allocation based material requirement on the order.

Allocations are soft

It’s important to understand that allocations in Job Shop are soft which means Job Shop does not prevent an allocated material from being used by a demand it was not originally intended for. For example if work on W-00033 shown in the inventory form above finished before W-00027, Job Shop would automatically deallocate the inventory from W-00027 and issue it to W-00033. Work order W-00027 would signal it needs to be replanned. Email notification can be set up to notify when these kinds of unexpected deallocations happen.

How lead times work

Job Shop uses the lead time on the product site inventory settings to calculate start dates for supply orders to fulfill demand by calculating backwards from the due date. The philosophy of lead times is that they should include a time buffer to account for unexpected events and capacity fluctuations to ensure products are available at the time they are needed. How the purchase order life cycle works#

Purchase orders are used to keep track of products or services you are buying from a supplier including but not limited to quantities, pricing, billing terms, delivery date and delivery information, so you know what is coming and when. Active purchase orders are shown by default in the Purchase Orders worksheet in the Buy workbook. You can create purchase orders manually from this worksheet, or automatically by converting one or more planned purchase orders to a purchase order. Job Shop will help you populate a new purchase order quickly by copying supplier and product information into the order when applicable. You can print a purchase order form to send to the supplier. You record the delivery of inbound materials with a purchase receipt.

Note: your workflow patterns may differ. See alternate workflows for more information.

Purchase order statuses

Purchase orders can be in one of the five states shown below, where they generally flow from pending to closed, though some statuses are optional depending on the business process.

The statuses work as follows:

  • Pending — This is the initial state of the purchase order before having been confirmed by the supplier.
  • Active — Purchase orders in this state have been released and are presumably confirmed by the supplier.
  • Receiving — Purchase orders automatically change to a “Receiving” state when a receipt is created for the order. This status is mostly informational but also prevents changing quantities while the order is in this status.
  • Back Order — This is a status that purchase order will go into after a receipt is posted if the quantities of items were not received complete. The purpose of backorder is to make it easy to identify active purchase orders that have at least been received partially.
  • Closed — The order changes to closed when all quantities have received complete, or if it is manually closed. At this point the purchase order is read only for historical purposes and no further receipts may be made on it.

How to purchase an outside process

The Buy module supports tracking purchase orders for an outside process on Pro and Enterprise editions. When you create a work order with operations that have a service set on them, Job Shop automatically creates a planned purchase for the outside process service. You can convert this planned purchase to a purchase order the same way as planned purchases for products. You can also keep track of what quantities you have sent out for outside processing by creating an outside process shipment against the purchase order. When shipped, Job Shop will report an operation completion on the work order related to the shipment that the operation has started. When the work is shipped back to your shop, your record a purchase receipt like any other purchase order. The difference is that instead of receiving goods in inventory, an outside process records a work order operation completion related to the operation that the purchase order is linked to.

  • Don’t record the shipment — You create the outside process purchase order, but you don’t bother to record the shipment, only the receipt. However, be aware that if you do record any outside process shipments, then you will not be allowed to receive a quantity greater than what you shipped.
  • Don’t record the shipment or receipt — If downstream operations from the operation with the service are reported complete, or a work order receipt is recorded, Job Shop will assume the outside process must have happened and update operation completion quantities with the assumed completions. However, do note if some purchase receipts have been recorded and shop floor users attempt to report an operation completion greater than what was received, the operation completion posting will fail.
  • Don’t create the purchase order — You may not even want to bother creating a purchase order at all but only include a service on the operation to support cost calculations. Again, if downstream operations record completions, then the operation with the service will be automatically completed even without a purchase order.

Work orders can be in one of the six states shown below, where they generally flow from unexploded to closed, though some statuses are optional depending on the business process.

Work order statuses

The statuses work as follows:

  • Unexploded — This is the initial state of a work order before it is saved, but once the save completes the work order explosion process is automatically run.
  • Pending — This is the initial state of the work order before having been released to the shop. Work orders in this state do not yet appear on dispatch lists and operation completions cannot be recorded against them.

Overview

Dispatch lists* are helpful to communicate to your shop floor what work order operations are available to be worked on. Furthermore, they are set by default to allow direct editing so that operators can record completions by simply clicking on a row, entering a quantity to complete, and saving. From this entry an operation completion will be automatically created and posted.

Standard dispatch list with quantities to complete being entered

What is shown

By default what is displayed on the list are all active or in-process operations with available quantities to be completed. When a work order that has any operations is released only the first operation displays as having available quantity to be worked on. Once quantities have been reported on the first operation the next operation, if there is one, shows as having available quantity to complete and is added to the dispatch list. When all quantities are complete on an operation, it closes and falls off the list.

Note there can be a lag of several seconds between when the completion quantity is saved until the row updates, is replaced, or removed from the screen due to the posting of the completion. This is because posting can involve performing several related transactions and updates on the work order that can take a little time. You can view the status of operation completions on their operation completion worksheet.

Customizing your dispatch lists

If there is any workbook in Job Shop that cries out for local configuration it is the Execution workbook and the dispatch worksheet. Shop floor operators are only interested in seeing the work that is relevant to their equipment or department. Likewise production managers generally want to make work lists as simple as possible to avoid errors. So you will likely want to tailor a variety dispatch lists named for specific work centers with filters that are relevant to them. For this your administrator will have to become acquainted with how to modify workbooks and worksheets to fit your work environment. Some suggested tactics you can take:

  • Copy the dispatch list worksheet in the Execution workbook so that you have a dedicated worksheet for each of your work centers, each one filtering on the labor resources, machine resources or description relevant to that team.
  • Copy the Execution workbook, one for each work center, and set the dispatch list to filter as appropriate for the team it is intended for. With this approach you can set authorization on the work book for specific user accounts so they will only see the ones appropriate to their work.
  • Alter the columns hiding unnecessary ones, or add columns with information helpful to evaluate the activity list.
  • Re-sequence the column order and widths via drag ‘n drop in a way that is most visually convenient for your workers.
  • Sort the list in the way that is most sensible to prioritize work appropriately.
  • You may also need to reconsider whether to show only operations based on available quantity as per the default filter. Especially if you are not recording completions on all operations, some may never get a chance to appear unless you remove that filter.
  • We highly recommend you set non-administrative users to have read-only authorization to any workbooks you create. Otherwise they are prone to change filters and columns in such a way that will be confusing to other users.

When you close the sale, the work has just begun!

Sales order statuses

Sales orders can be in one of the seven states shown below, where they generally flow from incomplete to closed, though some statuses are optional depending on the business process.

Sales order status list

The statuses work as follows:

  • Incomplete — This is the default state of sales orders. While in this state any items on the order cannot be planned or shipped. This is a good state to leave the order in when you want to create some record that you’ve received an order from a customer, but information such as billing, or products data are incomplete. If you create a new product to deliver to the customer that takes time to engineer, you can create the order with the product number, but leave the order status as incomplete until you are ready to purchase and manufacture materials.
  • Pending — When the sales order is in this state, the order is automatically planned where planned orders and work orders are created if necessary. Sales orders move into this state when the start action is executed, or if they are already active then unreleased. When a sales order is pending, it cannot be shipped.
  • Active — Sales orders in this state can be shipped and are changed to this state when they are released. Typically, this is also the time the sales order promise date is set, and confirmation forms are sent to the customer.
  • On hold — A sales order can be put in an on-hold status when it is in pending, active or back-order status. This will stop a sales order, and optionally its constituent work orders that are underway, from proceeding. This can be useful, for example, if credit, engineering, or approval problems arise that require intervention before any further transactions should be made. On hold is an on/off state separate from the order status, so the order remains in its previous status while on hold, but the red hand icon shows the on-hold condition. An order on hold cannot be shipped. When putting a sales order on hold, there is also an option to put child work orders on hold, so any production transactions are halted as well.
  • Shipping — Sales orders automatically change to a “Shipping” state when a shipment is created for the order. This status is mostly informational, but also prevents changing quantities while the order is in this status.
  • Back Order — This is an optional status that a sales order will go into after a shipment is shipped if the quantities of items were not shipped complete. However, this only happens if the shipment setting “Use back order” is on. Otherwise, the order goes back to an active state. The purpose of back order is to make it easy to identify active sales orders that have at least shipped partially.
  • Closed — The order changes to closed when all quantities have shipped complete, or if it is manually closed. At this point the sales order is read only for historical purposes and no further shipments may be made on it.

How the billing cycle works#

You use invoices to keep track of billing collections for products you have sold. They contain billing detail including but not limited to quantities, pricing, billing terms, delivery date and delivery information, so you know what was sold, when, and for how much. Active invoices are shown by default in the active invoices worksheet in the Bill workbook. You can create invoices manually from this worksheet, or automatically by converting an uninvoiced shipment into an invoice. Job Shop will help you populate a manual invoice quickly by copying customer and product information into the document when applicable. You can print an invoice form to paper or PDF to send to the customer, and you apply payment to invoices to keep track of what has been paid and what is still due.

Glossary

Glossary

Backflush#

An automatic transaction that records product demands required on a work order as being taken from inventory and consumed by the work order. A backflush may happen on either an operation completion or a work order receipt, depending on how material requirements on the work order are set up.

Demand#

A record that calls upon certain products or services that are needed to execute a business transaction. Sales order lines are a demand to ship goods and work order material requirements are a demand for products to make another product.

See also
  • Dependent Demand
  • Demand Signal

Demand Signal#

An indicator that demand is needed for a particular product. These take many forms in Job Shop:

  • The inventory worksheet in the Stock workbook shows the sum of demand for a particular product.
  • The reorder worksheet in the Plan workbook shows products sites with a planning policy of reorder point that are projected to fall below their reorder point based on demand.
  • The shortages worksheet in the Plan shows products sites with a planning policy of reorder point that are projected to fall below safety stock based on existing demand.
  • Planned purchase and work orders show signals to buy or make a specific quantity of a product to satisfy a specific demand. These are automatically created for product sites with planning policy of plan to order or make to order.
  • Alerts are created when projected quantities fall below a reorder point, safety stock or negative inventory thresholds, or when allocations against demands are removed before they are satisfied.
See also
  • Demand
  • Dependent Demand

Dependent Demand#

Demand needed by order that exists to satisfy an upstream demand. In Job Shop, work order materials are dependent demand. For example, suppose you have a sales order demand to ship bicycles and a work order to make bicycles ship on that order. The work order to build bicycles calls for wheels, and that call for wheels is dependent demand.

See also
  • Demand
  • Demand Signal

Economic Order Quantity (EOQ)#

The quantity used for costing purposes which presumes the ideal balance between minimizing setup time to make a product, without producing excess amounts of inventory that may go unused.

Feather#

A record type or class in the Featherbone definition system. Product, Work Order and Inventory Transaction are all examples of feathers. All worksheet pages in Featherbone are of a particular feather, as are relations associated with it. For example, Unit (of measure) is a feather relation on Products.

Natural Key#

The natural key is a unique number, code or other text information that is keyed in or otherwise visible on a relation within Featherbone. The natural key appears as a hyperlink on lists.

Site code, item number and unit of measure code are natural keys with hyperlinks on this list of inventory items

Relation#

A relation is a link between a record on one table with that on another. It acts as a kind of “pointer” to other related information in the system. For example, “supplier” is a relation on purchase order. Relations are visible hyperlinks on lists and a field with a special button to the left of the text on forms.

Supplier, site and contact relations on the purchase order form

On forms the natural key of the relation is in a text field, and additional label information is shown below that. In the above example the name of the supplier, the site description, and contact phone and email are shown as additional label information from the relation.

From Wikipedia:

A regular expression (shortened as regex or regexp), sometimes referred to as rational expression, is a sequence of characters that specifies a match pattern in text. Usually, such patterns are used by string-searching algorithms for “find” or “find and replace” operations on strings, or for input validation. A record that reports on products or services that are currently or will be available in the future. Inventory, Purchase Order lines, and Work Orders are all types of supply in Job Shop.
